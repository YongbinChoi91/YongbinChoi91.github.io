Framework / Linear algebra

Linear Solver Backend

A common CSR interface lets the nonlinear solver switch between direct and iterative solver packages.

Purpose

What this module does

This layer hides UMFPACK, PETSc, and MKL Pardiso behind one solve_linear_system_backend() call. PETSc-specific data such as FieldSplit, Schur, and PCD operators are prepared outside the physical weak form.

Direct solver

Factorize the assembled sparse tangent

UMFPACK is the default robust direct path. MKL Pardiso is an optional backend when an external MKL installation is available.

Assembled CSR tangentSparse factorizationNewton correction
Iterative solver

PETSc KSP and preconditioning

Krylov methods approximate the Newton correction through matrix-vector products. Their practical convergence depends on a preconditioner that captures the dominant operator structure.

PETSc KSPBasic PC or FieldSplitSchur / PCD for coupled pressure systems
Experimental

Matrix-free is not production-ready

The intended path applies Jv without assembling the global tangent. It is still under development and is not guaranteed to run correctly for every model, boundary condition, or preconditioner. This page documents the concept only; it is not a usage recommendation.

Backend options

  • Direct: UMFPACK and MKL Pardiso for robust reference solves.
  • PETSc KSP: GMRES, FGMRES, CG, and BiCGStab.
  • Basic PCs: LU, ILU, Jacobi, Hypre BoomerAMG, and GAMG.
  • Block PCs: FieldSplit with mechanical-pressure block layouts.

Design point

  • Compile-time backend availability is separate from runtime backend selection.
  • CSR sparsity pattern can be reused across Newton iterations.
  • Schur and PCD operators are backend capabilities; their physical interpretation belongs to the application pages.
