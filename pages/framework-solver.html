Framework / Nonlinear solve

Nonlinear Solver

The unified time-step solver controls Newton iterations, boundary conditions, adaptive stepping, diagnostics, and output calls.

Purpose

What this module does

The solver layer drives the global nonlinear problem. It builds boundary conditions, assembles the reduced system, calls the selected linear backend, updates the solution, accepts/rejects time steps, and triggers postprocessing.

Newton linearization

Correction equation

K(uk) Δu = −R(uk)

Each nonlinear iteration linearizes the assembled residual about the current trial state and asks the selected linear backend for a correction.

State update

Accept only a converged step

uk+1 = uk + Δu

Residual and increment norms control convergence. Material history and output state are committed only after the time step is accepted; failed steps may reduce the time increment and retry.

Algorithm

Predict state → assemble R,K → enforce constraints → solve correction → update → test convergence → accept or retry

Design point

  • Single-domain cases are treated as one-domain Problem objects.
  • Boundary duplicates and conflicts are diagnosed.
  • Assembly, linear solver, postprocess, and wall time are tracked separately.
Extension point

Keep nonlinear policy separate from physical models

Convergence criteria, time-step policy, and globalization may evolve without embedding model-specific equations in the solver driver.
