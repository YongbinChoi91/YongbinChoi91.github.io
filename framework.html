Framework Architecture

Follow the mathematical and computational path from problem input to postprocessed results, then open a stage for its basic algorithm and extension contract.

Framework

One framework, one computational path.

Each stage focuses on its numerical role. Source folders, files, functions, and full implementations remain in Code Structure.

01

Input

Problem, material, fields, boundary conditions, solver, and output controls.

 02

Mesh / DOF

FEM or VEM discretization, field spaces, connectivity, and global unknown layout.

 03

Weak Form / AD

Local residual definition and automatic consistent tangent extraction.

 04

Assembly

Element contributions scattered into the global residual and CSR tangent.

 05

Nonlinear Solver

Newton updates, constraints, convergence checks, and adaptive time stepping.

 06

Linear Backend

Direct or PETSc iterative solution of each Newton correction.

 07

Postprocessing / Output

Derived fields, visualization data, and VTK or HDF5 persistence.

Execution modes

Parallel and matrix-free paths

OpenMP accelerates element work, MPI distributes assembly and PETSc solves, and HDF5 supports scalable output.

Matrix-free — Experimental: under development and not guaranteed to run correctly for every model, boundary condition, or preconditioner.

Extension rule

Extend local physics and field definitions while preserving the shared assembly, nonlinear solve, and output contracts.
